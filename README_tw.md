# 豆瓣同步到 NeoDB

批量把豆瓣看過 / 讀過 / 聽過 / 玩過的條目同步到 NeoDB，標記日期沿用豆瓣上的標記日期（哪天在豆瓣點的看過，同步到 NeoDB 上就顯示哪天）。

## 安裝

1. 把 `douban-neodb-sync-1.0.7.zip` 解壓到一個文件夾（不要刪，插件要一直從這裏讀取）。
2. Chrome 打開 `chrome://extensions`，右上角打開「開發者模式」。Brave 操作一樣。
3. 點「加載未打包的擴展程序」，選擇解壓後的文件夾。
4. 點插件圖標，填好設置（見下）。

## 設置

- **NeoDB 站點**：默認 `https://neodb.social`。自建實例改成自己的地址。
- **NeoDB API Token**：在 NeoDB 網站 → 設置 → 開發者選項裏生成。Token 只存在本機瀏覽器裏，插件不會把它發給除 NeoDB 之外的任何地方。
- **同步內容**：勾選電影 / 書籍 / 音樂 / 遊戲。默認只同步「看過 / 讀過 / 聽過 / 玩過」（即 NeoDB 的 complete 狀態）。
- **同步評分 / 同步短評**：默認都勾選。評分按豆瓣 5 分制 ×2 轉成 NeoDB 10 分制。
- **標記可見性**：公開 / 僅關注者 / 僅自己。
- **僅試掃描**：默認勾選。先只掃描不寫入，看報告確認數量和匹配情況沒問題後，取消勾選再正式同步。

## 使用流程

1. 確認瀏覽器已登錄豆瓣和 NeoDB。
2. 第一次先勾選「僅試掃描」，點「開始同步」，看報告：豆瓣共多少條、多少條能在 NeoDB 對上、多少條失敗。
3. 沒問題後，取消勾選「僅試掃描」，再點「開始同步」正式寫入。
4. 同步中可以關閉彈窗，後台會繼續跑；點「暫停」可隨時停下（重新開始會從頭跑一遍，已寫入的條目重複寫入是安全的）。

## 修正之前同步錯的日期

如果你之前用別的工具同步過幾個條目，但日期寫錯了（比如寫成了同步當天），這次同步會把它們修正過來：

- 插件**不會跳過**已在 NeoDB 標記過的條目，每一條匹配到的條目都會按豆瓣數據重新寫入一遍，包括標記日期。
- 這一點有 NeoDB 自己的代碼作保證：NeoDB 的標記更新邏輯裏（`journal/models/mark.py` 的 `_update_shelf_member`），已存在且狀態相同（complete）的標記，傳入新的 `created_time` 就會覆蓋原來的標記時間，同時日誌時間也一起改；只改日期不會再發一條動態。
- 唯一例外：傳的日期如果晚於服務器現在的時間會被丟棄（按現在算）。豆瓣的標記日期都是過去的日期，不受影響。

建議先拿兩三條已同步錯日期的條目驗證一下：跑一次正式同步，去 NeoDB 上看那幾條的日期是否變成了豆瓣的日期，確認後再全量跑。

## 工作原理

1. **讀豆瓣**：插件在後台開一個豆瓣標籤頁，像你平時點開鏈接一樣，一頁一頁打開你的個人收藏頁（`movie.douban.com/people/你的ID/collect`、`book.douban.com/people/你的ID/collect`、`music.douban.com/people/你的ID/collect`，遊戲走個人主頁），每頁 15 條，間隔約 1.2 秒慢慢抓，避免觸發豆瓣的頻率限制。每一頁解析出標題、豆瓣鏈接、標記日期、星級、短評。用戶 ID 是插件自己從你登錄後的豆瓣首頁認出來的，不用你填。之所以不用後台直接請求，是因為豆瓣會給那種請求返回 404，只有像正常瀏覽一樣打開頁面才行；標籤頁是插件自己開的，不會動你自己的頁面，跑完可以隨手關掉。
2. **匹配**：對每一條調用 NeoDB 的 `GET /api/catalog/fetch?url=豆瓣鏈接`。已在目錄裏的直接返回條目；沒有的 NeoDB 會在後台新建（異步，15 秒後輪詢，最長約 2 分鐘）。
3. **寫入**：對每一條調用 NeoDB 的 `POST /api/me/shelf/item/{uuid}`，狀態 `complete`，`created_time` 傳豆瓣標記日期（當天 00:00，+08:00），同時帶上評分和短評。更新時總是發送完整內容——因為 NeoDB 有個規則：更新標記時不傳評分 / 短評 / 標籤，就會把原來的清空。

## 常見問題

- **豆瓣要求登錄或驗證**：豆瓣偶爾會彈驗證。去瀏覽器裏打開豆瓣任意頁面完成驗證（或重新登錄），再點繼續。插件不會替你繞過驗證。
- **Token 無效**：檢查 Token 是否複製完整、是否過期，重新生成一個填進去。
- **某幾條一直失敗**：報告裏會列出失敗的條目和原因。常見原因：該條目在 NeoDB 裏沒有且按豆瓣鏈接新建失敗（比如豆瓣鏈接不支持新建），或頻繁請求被限速（429）。可以單獨在 NeoDB 網站上手動標記這幾條。
- **同步很慢**：600 部電影大約 40 頁豆瓣列表（約 1 分鐘）+ 逐條匹配和寫入。NeoDB 裏沒有的條目每條新建要等 15 到 90 秒，這部分最慢；如果缺的條目多，整體可能要幾十分鐘。可以關掉彈窗讓它後台跑。
- **重複運行安全嗎**：安全。每次都是按豆瓣數據全量重寫，不會產生重複標記。

## 隱私

沒有服務器，所有處理都在你的瀏覽器本地進行。豆瓣登錄狀態只用於讀取你自己的列表頁；NeoDB Token 只發給你的 NeoDB 站點。

## 更新記錄

- **v1.0.7**：NeoDB 限速（429）時自動重試——匹配和寫入各最多重試 3 次（等 5 秒、15 秒、30 秒），不用整輪重跑去撿漏網的條目。
- **v1.0.6**：修復“task is not a function”崩潰——並行取任務時有競態，多出的工人會取到空任務；現在取任務是原子的。另外修了新建階段“待新建”數量的顯示。
- **v1.0.5**：換地址——`/mine/watched` 這種快捷地址豆瓣已經撤掉了，自己打開也是 404 再跳回首頁。現在改走個人收藏頁（`…/people/你的ID/collect`），用戶 ID 從登錄後的豆瓣首頁自動識別。
- **v1.0.4**：打開列表頁改成從頁面裏跳轉過去（帶上豆瓣的來源信息，盡量接近人點鏈接的樣子）；如果還是 404，日誌裏會寫清楚最後停在哪個地址、頁面標題和內容，方便定位原因。
- **v1.0.3**：改走“打開頁面再讀內容”的方式——豆瓣連頁面裏發出的請求也返回 404，只有像正常瀏覽一樣打開列表頁才行。現在插件用一個自己開的後台標籤頁逐頁打開列表再讀取，速度會慢一點（約 600 部電影大約兩分鐘），但不再 404；如果這個瀏覽器裏沒登錄豆瓣，會明確提示登錄。
- **v1.0.2**：修正已打開的豆瓣頁面上連不上的問題——更新插件前就開著的豆瓣頁面裏沒有同步助手，現在會直接給它裝上，實在不行再新開一個標籤頁；日誌裏會寫清楚卡在哪一步。
- **v1.0.1**：豆瓣請求改走頁面標籤頁發出，修復直接請求被豆瓣返回 404 的問題；識別豆瓣未登錄時的 `error code: 008` 提示。
- **v1.0.0**：第一版。
